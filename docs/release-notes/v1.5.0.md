# v1.5.0

**配置彻底分离**：每个 Windows 用户只认自己的 `$DSH_HOME/remote-access-config.json`，
插件不再读也不写共享 profile（`cordis.patch.yml`）。

## 为什么改

1.4.2 起虽然把配置存到了本用户 JSON，但仍然是「本地优先、共享兜底」：设置页保存写的还是
profile 的 `cordis.patch.yml`，启动时还要拿它当基线。结果就是配置并没有真正分离 ——
多个用户共用一份 profile（`.dsh\profiles\desktop` 做成 junction）时，任何一次保存仍可能
碰到共享配置。

1.5.0 把这层关系整个去掉：

- **插件不导出 `Config`、不做 DSH 配置表单**；bundle patch 的插件行不带 `config`；
- 启动时**只**读 `$DSH_HOME/remote-access-config.json`（不存在就按代码默认值建一份）；
  DSH 传进来的 config 一律忽略；
- 设置页（本机与手机）都走本插件自己的 `/__remote_access__/config`：
  `GET` 读、`POST { patch, revision }` 写，写盘完成后**先回执、下一拍再重挂监听**
  （否则重挂会 `closeAllConnections()`，把这次保存的连接自己掐掉）；
- 错密码拉黑直接写这份 JSON 的 `denyCidrs`，不再经过 `configEditor`；
- 端口被占用仍会自动换空闲端口，并把实际端口写回本文件。

## 升级注意

1. 升级后**重启一次 DSH**（`index.js` / `client.js` 都改了）；
2. 1.4.x 存在 profile 里的参数（端口 / 网段 / 密码）**不会被读取**：到「设置 → 远程访问」
   重新填一遍，或直接编辑本用户 JSON；
3. 1.4.2–1.4.4 用户的本用户 JSON 已经存在，里面就是上次的生效值，通常不用改；
4. 这一版**没有重发 APK**：外壳代码没动，仍是 1.4.1（`versionCode` 16）。

## 文件形态

```json
{
  "version": 1,
  "note": "本文件是当前 Windows 用户自己的远程访问配置（唯一配置源）……",
  "updatedAt": "2026-10-19T00:00:00.000Z",
  "config": { "port": 19388, "allowCidrs": ["100.64.0.0/10"], "……": "……" }
}
```

未知键会被忽略；也可以只写一个扁平的配置对象（不包 `config`），插件照常读。
