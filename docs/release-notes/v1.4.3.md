# v1.4.3

**内部修复（功能与 1.4.2 相同）**：热重载不再重新推导本用户配置路径。

## 修了什么

`app-boot/config-reload` 的处理（`reapply()`）以前会用「刚从 settings 读到的配置」重新推导
`<DSH_HOME>/remote-access-config.json` 的路径。真实 DSH 里这个字段总会出现在 settings 视图里，
所以对用户行为与 1.4.2 一致；但当视图缺少 `localConfigFile` 时（例如测试桩），归一化会填回默认值，
于是把配置写进了真实的 `$DSH_HOME` —— 1.4.2 的测试就是这样污染了开发机的 `.dsh`。

现在 `localConfigFile` 被当作**启动期引导字段**：

- 路径只在 `apply()` 时确定一次；
- 热重载沿用这份路径，不再从 settings 视图重新推导；
- 它也不参与「本用户配置 vs 共享 profile」的差异比较。
