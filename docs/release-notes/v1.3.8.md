# v1.3.8

手机端四件事：**一轮结束也会提醒你**、**回车不再发送**、**大资源不再每次重传**、设置页整页整理。

> 这一版**插件与 APK 都是 1.3.8**（`versionCode` 13 → 14 → 15）—— 结束通知要外壳认识新的载荷，
> 所以 **APK 需要重装**；`index.js` 也改了（事件监听、缓存头、自检端点）→ **要重启一次 DSH**。

## 修：同一条消息弹两次 / 切回后台又弹

两条链路各有一个坑，都补掉了：

- **宿主**：`agent/status` 不保证「running → idle」只出现一次（维护 / 压缩这类中间态也会映射成 idle），
  于是**一次消息报了两次「结束」**。现在规矩是「**一次 `running` 只兑现一次结束**」，
  没有 `running` 过的 `idle` 一律忽略。
- **外壳**：App 切到前台时那条前台服务会被停掉，切回后台是**新实例** —— 去重状态只放在内存里，
  同一条结束（或同一条待答）就会被当成新的再弹一次。现在去重键（结束 = `<宿主实例>:<编号>`，
  提问 = 内容指纹）**持久化在 SharedPreferences 里**；宿主重启后编号从头数也不会误判
  （靠载荷里的 `boot` 实例标记区分）。
- **「提问」那条按你的要求改了**：切前台**不再撤回**通知与指纹（原来撤回时会把指纹一起清掉，
  等于「从没提醒过」，回来自然又弹），所以**切前台再切回后台不再重复弹**；
  只有「问题答完了」或「关掉通知开关」才撤回。你手动划掉那条通知也不会再弹；**新问题**照旧会响。

## 一轮结束时通知手机（正常 / 异常）

原来只有「模型提问」会提醒你；现在**跑完一轮**也会弹一条，走**独立的「任务结束」通道**
（与「模型提问」分开，想静音哪一类都行）：

- **正常跑完**：`这一轮跑完了 · 用时约 3 分 12 秒`；
- **异常结束**：带上分类 —— 依据是 **DSH 自己的错误码**，不是猜的：
  `MALFORMED_RESPONSE`（模型输出格式错）、`QUOTA` / `ACCOUNT_QUOTA`（余额 / 额度不足）、
  `AUTH` / `INVALID_CREDENTIAL`（凭据失效）、`RATE_LIMIT`（被限流）、`CONTEXT_WINDOW_EXCEEDED`（上下文超长）、
  `SERVER`（服务端错误），网络那一族看 Node 的 errno；认不出来就老实说「出错」并带上原文。
- 触发条件与「提问」完全一致：**电脑窗口不可见 + 你没在看手机**（两个开关互不影响：`notifyOnFinish`）；
- 结束判定用 DSH 的事件 `agent/status`（`running → idle`），带 **2 秒防抖**（循环里的维护 / 压缩中间态
  不会被误报），并且**只认主流程** —— **子任务跑完不打扰你**；
- 刚跑完那一条有 **5 分钟新鲜窗口**：在页面上看着它跑完、然后切出去，照样收得到；
- 正文只写结论与用时（异常写分类与原因），**绝不带模型回答内容**（可能很长，也不该出现在锁屏上）；
- 设置页页脚的自检现在**两个通道分开报**：`提问通道=4、结束通道=4`（哪个被调低一眼看出来）。

## 手机端回车 = 换行，点「发送」才发送

手机上的回车键本来就小，官方语义下它直接发送，想写两行只能去凑 `Shift+Enter`。现在：

- 手机布局**或**触摸设备上的主输入框里，裸回车**插一个换行**，只有点**发送**按钮才真正发送；
- `Ctrl/Cmd+Enter` 仍然是发送，`Shift/Alt+Enter` 保持原样；
- **输入法合成中（含刚合成完 60ms 内）一律放行** —— 中文输入法用回车确认候选词，吃掉它等于打不了字；
- 别的输入框（设置页、排队消息的行内编辑器）一律不碰，**本机（电脑）页面完全不受影响**；
- 不想要这个行为：设置 →「远程访问」→ 关掉「手机端回车=换行」。

实现方式是在**捕获阶段**把这一个按键吃掉（官方那条「回车发送」根本收不到），再自己往编辑器里插换行；
三条路依次试（合成 `beforeinput/insertLineBreak` → `execCommand('insertLineBreak')` → 合成 `Shift+Enter`），
三条都不成时也**什么都不做**，绝不退回「发送」。

## 手机端资源缓存：壁纸那类大文件不再每次重传

「每次进去都要重下十几 MB」的根因**在上游**：

- `/assets/*` 那两个 Vite bundle（实测 1.42 MB）上游只发 `content-type`，**没有** `cache-control` / `etag` / `last-modified`；
- 壁纸那类文件族（几十 MB 的图 / 视频）同样什么缓存口径都不发，也没有 `ETag`；
- 于是浏览器既没有 freshness、也没有校验器，只能整份重下（APK 侧并没有禁用缓存，不是它的锅）。

这一版由代理把响应头喂对，并把「条件请求怎么判」接过来：

- **内容寻址**（`?rev=…`、`index-5SrrfWpU.js` 这种哈希文件名、64 位 hex 的附件 id）→ `immutable`，一年不再问。
  判定改成**通用规则**（URL 里真有内容哈希），不再写死 `/plugins/`、`/assets/` 两个前缀 ——
  顺带修掉「非哈希的插件文件被钉一年」这个隐患。
- **上游已给校验器**（`ETag` / `Last-Modified`）→ 只补新鲜期，校验器原样保留，条件请求仍由上游回答。
- **上游什么都没给的大静态文件** → 补 `private, max-age=10 分钟, stale-while-revalidate` 与**自铸的弱校验器**：
  期内手机一次请求都不发；过期后先出旧图、后台只做一次**头部级**核对，对得上就回 **304（零字节）**。

校验器用「长度 + 类型 + 首/尾各 64 KB 片段」（可关），**不整份哈希、不落盘**，
所以「换了图但字节数一模一样」也不会被误判成没变；≤256 KB 的小文件直接缓冲整份算精确哈希。

**宿主不落任何正文，也不读宿主的文件系统**：资源在哪个盘、哪个 Windows 用户的空间、
是不是软/硬链接搭出来的共用目录，对这套逻辑都透明（只看 URL 与上游响应头），
因此也不会出现「A 用户的缓存被 B 用户读到」。缓存容量交给手机自己的 Chromium LRU，我们不做第二份账。

不碰的范围（默认）：`no-store` / `no-cache` / HTML 导航 / JSON 接口 / 小块二进制 / 带 `Range` 的请求。

**流量账（1.3.8 加的排查工具）**：「缓存」那一组里除了口径与计数，还会列出**本轮按 URL 的字节数** ——
送出多少、其中多少「没有缓存口径」（= 下次还会重传）、**每个 WebSocket 通道各推了多少**，
并给每一行附一句**为什么没带缓存口径**（`上游写了 no-store` / `带 Range 的分段请求` /
`类型不在白名单（…）` …）。配一个「清零流量账」按钮：先清零 → 完全退出 App → 重新打开 → 回来看这几行。
同一份数据也在状态文件里，接口是 `GET /__remote_access__/cache`（`?reset=1` 清零）。

**两个「逆着上游意愿」的开关**（默认都关，实测里最大那两笔就出在这儿）：

| 开关 | 治什么 | 代价 |
|---|---|---|
| `cacheOverrideNoStore` | 上游给实时抓帧/预览图写 `no-store`，可那一张实测 **4.03 MB**、每次进页面都重来。开着时只对**图片/音频/视频**、且**确实够大**（探针读完 ≥64 KB，分块传输没长度头也算数）的响应补新鲜期 + 弱校验器 | 最多看到「新鲜期」这么久之前的旧帧；实时小端点（如每秒一次的频谱，JSON）不碰 |
| `cacheFullRange` | 媒体元素取音轨发 `Range: bytes=0-`，上游回覆盖整份的 206，而**浏览器永远不缓存 206** —— 实测一次进页面重下 **3.8 MB × 2**。开着时把这一种改写成可缓存的整份 200（字节一模一样） | 个别播放器可能失去拖动定位；中间分段（`bytes=100-200`）一律原样透传 |

**有些流量是任何 HTTP 缓存都救不了的**，别指望它：聊天里的图片/附件走 RPC（`readAttachment`，
`WS /api/remote.mux`），客户端只把它缓存在**页面内存**里 —— 所以「从最近任务划掉 App」＝整页重载＝图片重来，
而只是**退到后台再回来**不会重载、也就不重取；实时轮询（动态壁纸的音频频谱，实测约 8 次/秒）缓存它只会把动画弄坏。

## 可调项（都在设置页「远程访问」里）

| 项 | 默认 | 说明 |
|---|---|---|
| 手机端回车=换行 | 开 | 关掉即恢复官方「回车即发送」 |
| 启用手机端缓存 | 开 | 总开关；关掉后一个缓存头都不加 |
| 新鲜期（分钟） | 10 | 1–1440；期内手机零请求，过期后先出旧的、后台核对一次 |
| 过期时取首/尾片段核对 | 开 | 治「换了图但字节数一模一样」；关掉就只按长度+类型核对 |
| no-store 的大媒体也缓存 | 关 | 治「实时抓帧一次 4 MB、每次进页面都重来」 |
| 整段 Range 当整份缓存 | 关 | 治「音轨每次重下 3.8 MB × 2」 |
