# v1.4.1

**修复 DSH 0.2.1 启动崩溃**：插件 loader 行 id 与官方新增的 `remote-access` 行重名。

> 如果你在 1.4.0 上遇到 `desktop welcome: Web request failed` / “应用无法启动”，这一版就是修复。
> 升级后需要把旧 `cordis.patch.yml` 里 `id: remote-access` 的 `config:` 挪到
> `id: remote-access-cidr` 下面；不挪则参数回默认值，但不会再撞官方行。

## 根因

DSH 0.2.1 的 `@deepseek-ai/dsh-base` 新增了一行：

```yaml
- id: remote-access
  name: '@deepseek-ai/dsh-api-remote-access'
```

本插件 1.4.0 的 bundle patch 也用了同一个 loader id：

```yaml
- id: remote-access
  name: 'dsh-plugin-remote-access'
```

loader 行 id 必须全局唯一。重名后官方的 `remoteAccess` 服务不挂载，
`typert-gateway` / `settings-controller` 等依赖它的行一直 pending，
桌面壳启动时 `settings/describe` 请求失败，于是报：

```
desktop welcome: Web request failed
```

插件自己的诊断里能看到它已 apply、已监听，但宿主核心服务并没有起齐——这两件事并不矛盾。

## 修复

- 插件行、设置命名空间、`Config` 的 `ROW_ID` 与 `client.js` 的 `NS` 全部改为
  **`remote-access-cidr`**（旧包名式的名字，和官方行彻底分开）；
- `cordis.patch.yml` 的插入行改为 `id: remote-access-cidr`；
- `tools/check-dsh-compat.mjs` 增加检查：读取 0.2.1 官方 `dsh-base` / `dsh-web-app`
  的 patch，断言插件行 id 不与官方行重名；
- 测试夹具中的命名空间同步改为 `remote-access-cidr`。

这也解释了插件页「启用」时的
`session-controller: file-upload: Agent resolver is already registered`：官方
`remoteAccess` 服务没挂载，session-controller 在热启用时被反复激活。id 分开后，
官方服务与插件行各自独立，热启用不再撞这条链。

## 升级注意

1. 升级到 1.4.1（第一次装/升级仍建议冷启动一次，让 loader 行换成新 id）；
2. 打开 `$DSH_HOME/profiles/desktop/cordis.patch.yml`，把旧 `id: remote-access` 下的
   整段 `config:` 复制到 `id: remote-access-cidr` 下（没有这一段就用默认值）；
3. 冷启动后，插件页的启用 / 停用走热重载即可，不再需要每次重启；
4. 启动后到「设置 → 远程访问」确认能看到表单。

## 测试

- Node 22 与 Node 24.21（桌面端内置 Electron Node）双跑：
  - `tools/test-remote-access.mjs` 160/160
  - `tools/test-client.mjs` 123/123
  - `tools/check-config-schema.mjs` 12/12
  - `tools/check-dsh-compat.mjs` 15/15（含 loader id 唯一性检查）
- 用修好 id 的本地包跑 `dsh --profile test --dump-config` 实测：组合里
  官方 `id: remote-access`（`@deepseek-ai/dsh-api-remote-access`）与插件
  `id: remote-access-cidr`（`dsh-plugin-remote-access`）并存，不再重名。
- **热启用/热停用实测**：在临时 profile（`@deepseek-ai/dsh-base` + `@deepseek-ai/dsh-web-app`，
  1.4.1 已安装但未启用）里启动真实 DSH 0.2.1 Host，通过
  `pluginManager/setBundleEnabled` 依次热启用、热停用，两次都返回：

  ```json
  { "application": "applied", "warnings": [] }
  ```

  不再出现 `session-controller: file-upload: Agent resolver is already registered`。
- **真实桌面端热加载**：在当前 DSH 0.2.1 桌面端里把 1.4.1 文件装进 profile、
  把 bundle 加进 `dsh.profile.bundles` 后，HMR 直接热加载插件：状态文件出现
  apply / 监听 / 上游自检，进程未崩、无需重启。

> 1.4.1 已在本机 DSH 0.2.1 桌面端热加载验证；仍未发布 npm / GitHub Release。
