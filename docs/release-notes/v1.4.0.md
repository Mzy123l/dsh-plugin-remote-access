# v1.4.0

**适配 DSH 0.2.1**：端口不再写死、支持原生 HTTPS，远程外观/字号只改手机不写电脑设置，并按 dshmarket 要求声明版本要求。

> **版本要求**：`engines.dsh = ^0.2.1-rc.1`（覆盖 `0.2.1-rc.1` / `0.2.1-rc.2` 与后续 0.2.x）。
> **DSH 0.2.0 及更早请继续用 1.3.8** —— 这一版用到了 0.2.1 的 `webServer.getOrigin()`、
> 远程设置持久化与 `theme.setFontSize(role, px)` 等行为。
>
> 插件与 APK 不总是同号：这一版只动网页半区与宿主半区，**APK 仍是 1.3.8，不用重装**。
> 宿主半区有改动（`index.js`），升级后**重启一次 DSH**。

## 适配 DSH 0.2.1

### 桌面端改用系统分配端口：上游自动跟随

0.2.1 的桌面端不再固定 19387，`upstream` 写死端口会连不上。现在：

- `upstream: auto` 优先读 `ctx.webServer.getOrigin()`，一次拿到**协议 + 真实监听端口**；
- `cordis.patch.yml` 的默认值从 `http://127.0.0.1:19387` 改为 `auto`；
- 读不到 `getOrigin()` 时，退回 `webServer.port` / `protocol` / 环境变量；
- 状态文件里会写明最终选中的上游协议与端口，排查时不用猜。

### 支持 0.2.1 的原生 HTTPS

0.2.1 的 Web 可以自己开 HTTPS（`--tls-cert` / `--tls-key`）。本版把整条链路都改成按上游协议选客户端：

- 普通 HTTP 代理、缓存探针、401 补票重试都用 `https.request`；
- WebSocket 透传改用 `tls.connect`；
- `Host` / `Origin` 按实际协议改写（`https://` 而不是永远 `http://`）；
- 只连本机回环，因此接受 DSH 的自签证书（`rejectUnauthorized: false`）。

### 远程「外观 / 字号」只投影本页，不写电脑设置

0.2.1 的 ui-settings **取消了**「非回环页面 → memory」的降级：`ConfigFormController` 不再有
`persistence` / `mode`，远程页面调官方 setter 会**直接写宿主设置**。沿用 1.3.8 的做法，
手机会把电脑的主题/字号一起改掉。本版改为：

- **外观**：只设置本页 root 的 `color-scheme`、`data-ds-theme-source`、body 的 `data-ds-dark-theme`；
  **不调用** `theme.setTheme`；
- **字号**：只写 body 的 `--dsh-content-font-size` / `--dsh-code-font-size` / `--dsh-terminal-font-size`；
  **不调用** `theme.setFontSize`；
- 电脑端改主题会广播 `theme/change`，手机页在官方 presenter 之后重新投影自己的外观；
- 控制器退出时把本页恢复成宿主当前的主题/字号，仍然不触发写盘；
- 0.2.0 上继续走官方 setter（本页生效），`theme.setFontSize` 的单参/双参签名都兼容。

### 「工作步骤展示 / 显示代码工作视图 / 性能与用量」改为跟随电脑

0.2.1 只提供「写宿主」的公开入口，没有「只改本页」的路径。继续调用就等于替你改电脑，
所以本版**不再远程覆盖**这三项：它们跟随电脑设置，设置页「UI 设置」的状态行会如实写明。
0.2.0 上仍然照旧生效。想改这三项，请到电脑的官方「通用设置」里改。

## 按 dshmarket 要求补齐清单

- `package.json` 增加 `engines.dsh = ^0.2.1-rc.1`：dshmarket 的「按宿主发现」与安装前兼容性检查都读它；
  已用 DSH 0.2.1 自己的 `evaluatePluginCompatibility` 实测通过（运行时 `0.2.1-rc.2`）。
- 增加 `./icon.svg` 导出，配合 0.2.1「显示文本与图标走子路径导出」的约定。
- 更新 `locale/{zh,en}.json` 与 `meta.description`，写明 0.2.1 适配与远程 UI 的新行为。
- 新增 `tools/check-dsh-compat.mjs`：用安装目录里的 `dsh-app-boot` 与
  `dsh-plugin-market-index` 校验 `engines.dsh`、bundle patch、客户端面、locale/icon 与市场索引形状。

## 测试

全部在 Node 22（开发机）与 **Node 24.21（DSH 桌面端内置 Electron 的 Node）** 下跑过：

```
node --check index.js
node --check client.js
node tools/test-remote-access.mjs   # 160/160
node tools/test-client.mjs          # 123/123
node tools/check-config-schema.mjs  # 12/12
node tools/check-dsh-compat.mjs     # 13/13
```

新增覆盖：

- `parseUpstream` 保留 `http:` / `https:` 协议；`resolveUpstream` 从 `getOrigin()` 读到 0.2.1 的随机端口，
  并跟随 `webServer.protocol=https`；
- 0.2.1 的 UI 设置：**一个会写宿主的官方入口都不调用**；外观与字号真的落到本页 DOM；
  电脑端 `theme/change` 之后手机仍保留自己的外观；出厂值 `default` 也走本页投影；
- 0.2.0 的旧路径（单参 `setFontSize`、五个官方入口）保持原样通过。

> 没有在运行中的 DSH 桌面端里启动插件做真机验证（按你的要求先不启动，避免把 DSH 带崩）。
> 发布前如需最后一关，建议在 DSH 0.2.1 里安装后：

1. 打开「设置 → 远程访问」，确认「本页客户端版本 1.4.0」；
2. 手机上打开远程页，确认外观/字号生效、电脑设置不被改；
3. 查看 `<DSH_HOME>/remote-access-url.txt` 里的上游协议与端口是否与本机 DSH 一致。

## 安装

```sh
dsh plugin --profile desktop add dsh-plugin-remote-access
# 或在 DSH 插件页填 dsh-plugin-remote-access
```

升级后重启一次 DSH。
