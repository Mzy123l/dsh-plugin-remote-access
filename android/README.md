# DSH · 安卓外壳

把电脑上 DSH 的**远程访问网页**装进一个安卓 App。手机装一次，之后只管填地址。

## 它做了什么

| | |
|---|---|
| 首屏 | **服务器地址页**：只填 `IP或域名:端口`（**不带协议**，例 `100.64.0.3:19388`）；HTTPS 由勾选决定 |
| 失败时 | WebView 打不开（地址错 / 电脑没开 / 不在同一网段）**自动退回地址页**并说明原因 |
| 顶栏 | 网页上是左侧一枚半透明小胶囊（**设置 / 刷新**两枚图标）；**设置页任何时候都进得去**，断网也能改地址 |
| 返回键 | **整个由外壳接管**（见下面「返回键」一段）：先关网页里的抽屉/右栏/设置面板 → 再网页历史后退 → 最后**退到后台**（不退出） |
| 通知 | **模型提问时弹状态栏通知**（见下面「模型提问时的通知」）：退到后台后由一条前台服务盯着，电脑窗口不可见 + 你不在看 App 时才响 |
| 网页 | 就是电脑上那份 DSH：手机布局、`远程UI布局`、`UI 设置` 全由插件配置决定 |
| 权限 | `INTERNET` / `ACCESS_NETWORK_STATE` / `POST_NOTIFICATIONS` / `FOREGROUND_SERVICE(_SPECIAL_USE)`；允许明文 http（Tailscale 网段内直连） |
| 其它 | 附件选择（`ACTION_GET_CONTENT`）、站外链接交给系统浏览器 |

地址存在 `SharedPreferences`（`dsh_remote`）里，下次打开直接连。

## 返回键

返回键不分给系统默认行为，而是按当前屏幕逐档决定（`MainActivity.handleBack`）：

| 当前屏幕 | 返回键做什么 |
|---|---|
| 地址页（从网页点「设置」进来） | 回网页，**不重新连**、不丢页面状态 |
| 地址页（首次启动，或网页已经坏了） | 退到后台（没有「回去」可回） |
| 错误页 | 回地址页改地址 —— 主框架加载失败之后 WebView 里已经没有能看的页面了，「回网页」只会退回一张白页，所以那一档不做 |
| 网页，手机布局里还开着抽屉 / 右栏 / 设置面板 | **先关掉最上面那层**（走它自己的关闭入口：官方浮层派发 Escape、抽屉点「收起侧边栏」），这一下返回键就此用掉 |
| 网页，主区停在「插件 / 自动化任务」这类**全局面板**上（左上角面板列表选中的那个） | 回会话 —— 走官方 `layout.selectPanel(null)`，与手点左上角那个会话图标同一条路 |
| 网页，没有浮层可关，但 WebView 有历史 | 网页后退 |
| 都没有 | **退到后台**（`moveTaskToBack`），**不退出 App** |

最后一档从「退出」改成「退到后台」是 1.3.1 起的行为：退到后台之后 App 还活着，
模型在电脑上提问时才能在状态栏提醒你（见下一节）。真要退出，从最近任务里把它划掉即可 ——
那时前台服务会跟着一起收掉，不会有残留通知。

「网页已经坏了」由主框架导航成没成来判：`onPageStarted` 清标记、`onReceivedError`（只认主框架）立标记，
`onPageFinished` 到的时候没有标记才算「这一版真的渲染出来了」（`webOk`）。地址页那个返回图标看的是同一个标记。

三处实现上的取舍：

1. **两条返回路径都接上**。Android 13（API 33）起系统把返回交给 `OnBackInvokedCallback`
   （清单里 `android:enableOnBackInvokedCallback="true"`），更早的版本只有 `onBackPressed`；
   两条路都进同一个 `handleBack`，所以新旧机器行为一致。代价：返回键由我们裁决，
   系统就不再画「滑回桌面」的预测式预览 —— 换来的是任何一层都有确定的返回行为。
2. **问网页是异步的**。抽屉 / 右栏 / 设置面板 / 全局面板都是浏览器半区（插件 `client.js` 的
   `window.__dshRaBack`）回答的，WebView 没有同步的询问入口，所以返回键会先
   `evaluateJavascript` 问一次「还有几层能关的」；网页线程卡住时 400ms 后按「没有浮层」处理，
   免得返回键看起来失灵。普通浏览器（没有外壳）里没有这个入口，网页那半边等于不存在。
3. **两端要配套**。返回键的「网页那一半」在插件里，不在 APK 里：**APK `1.3.0` 起 + 插件 `1.3.0` 起**
   （`window.__dshRaBack` 是 1.3.0 加的；1.3.1 只是把最后一档从「退出」改成「退到后台」）。
   装了新 APK、电脑上还是老插件时，`window.__dshRaBack` 不存在
   （外壳问不到浮层），于是照旧「网页后退 → 退到后台」—— 表现就是「抽屉开着按返回仍然直接退到后台」。
   这不是 APK 的 bug，把插件也更新到同一版即可（插件页里把版本号/提交更新一次，重启一次 DSH）。
   反过来，**只加一层网页浮层不用重打 APK**（外壳问的永远是那两个函数）。

## 模型提问时的通知

模型问你「要用哪个方案？」这类选择时，如果**电脑上的 DSH 只有托盘、没有窗口**，而你**没在看手机**，
屏幕上会**从顶部弹出一条横幅**（heads-up，像收到一条微信：会响、会震、几秒后收进状态栏）；
答完（在 App 里答或在电脑上答）它自己消失，点它回到 App。

```
宿主插件 ──记录「谁在等回答」+ 收「窗口可见吗」──►  /__remote_access__/notify（长轮询，带鉴权）
                                                        ▲
WatchService（前台服务）─────────────────────────────────┘   App 退到后台时起来
```

### 为什么要弹出横幅、靠什么弹

Android 上「从顶部弹出来」不是通知里的一个开关，而是几条一起成立才行。这一版逐条落实：

| 条件 | 这里怎么做的 |
|---|---|
| 通道重要性必须是 `IMPORTANCE_HIGH` | 「模型提问」通道建的时候就是 HIGH（横幅的总开关；用户手动调低就只能去系统设置改回） |
| 通知要是高优先级「消息」 | `PRIORITY_MAX` + `DEFAULT_ALL` + `VISIBILITY_PUBLIC` + `CATEGORY_MESSAGE` + `setTicker` |
| **必须是新通知** | 两个 id 轮流用（`1002` / `1003`）：**更新同 id 的旧通知时系统不保证再弹一次横幅**，所以每条问题都当新消息发，旧的那条顺手撤掉 |
| 不能被静音/仅提示一次 | `setOngoing(false)` + `setOnlyAlertOnce(false)` |
| 常驻那条别来添乱 | 「后台待命」通道**故意**是 `IMPORTANCE_LOW`：不弹、不响、不震，只做前台服务的本职 |

**「我只看到状态栏里一条不弹的通知」**：那几乎一定是常驻的「后台待命」那条（外加电脑上的插件还没更新，
它才会写着「插件版本太旧」之类）。真正会弹的是「模型提问」通道那条，只在**真的有问题在等**时才出现。

剩下三种「弹不出来」代码管不了：系统设置里「DSH → 通知 → 模型提问」被关成静音、或关了
「横幅 / 悬浮通知」（国产 ROM 里常见，位置在通知分类那一层）、以及开着勿扰模式。
另外 App 就在前台时也不弹 —— 那时问题卡片本来就在眼前，不重复打扰。

- **为什么是前台服务**：App 一退到后台，WebView 那一半随时可能被系统掐掉（JS 被节流、进程被回收），
  而这条通知要的恰恰是「人不在电脑前」的时候。所以 `WatchService` 自己发 HTTP 长轮询
  （带着 WebView 里那张放行 cookie：设了访问密码时是插件发的那张，否则是 DSH 自己的），
  由前台服务把进程保成「活着但不可回收」。
- **只做一件事**：宿主算好「有没有待答选择 / 电脑窗口可不可见」，这里只判断该不该打扰用户 ——
  不解析网页、不碰会话数据。判据三条同时成立才响：有待答 + App 不在前台 + 电脑窗口不可见。
- **长轮询而不是定时轮询**：带着上次的 `rev` 问，状态没变就一直挂着（最多 20 秒），
  一变立刻返回 —— 通知几乎是实时的，而请求量只有每分钟两三次。
- **常驻那一条**：Android 要求前台服务必须挂着一条通知，所以 App 在后台时状态栏有一条
  「DSH 后台待命」（`IMPORTANCE_LOW`、不响、不震、**不弹**），文案会跟着状态变（「你正在看 App，
  模型提问会显示在页面上」/「电脑上的 DSH 窗口正开着，不打扰你」/「连不上电脑上的 DSH，正在重试…」）。
  **回到 App 时服务会停掉**，那条常驻通知也跟着消失。
- **权限**：Android 13+ 的 `POST_NOTIFICATIONS` 在**第一次退到后台**时问一次（`onUserLeaveHint`）；
  点了「不允许」就不再问，想开去系统设置里打开「DSH → 通知」。
- **连不上怎么办**：分三种，常驻通知上那行字会直接说清是哪一种 ——
  - `电脑上的插件版本太旧（没有通知接口），去电脑上更新它`：电脑上的插件还是 1.3.1 之前的版本；
  - `登录凭据已过期：打开 App 重新输一次访问密码`：放行 cookie 过期了；
  - `连不上电脑上的 DSH，正在重试…`：退避重试（5s、10s…封顶 60s），连续 5 分钟连不上就自己收工
    （下次打开 App 会再起来）。

  前两种是「等你处理」，所以不退避、也不收工，改成每分钟重试一次 ——
  在电脑上更新完插件（或重新解锁）之后，手机不用再动就会自己接上。
  **这三句话是 1.3.3 才分开的**：以前一律说「连不上电脑上的 DSH」，把「电脑上的插件太旧」
  这个最常见的原因说成了网络问题 —— 真机上就是这么被绕了一圈的。
- **两端要配套**：这条链路是 APK `1.3.1` + 插件 `1.3.1` 一起加的（插件现在到 1.3.3，
  接口没变）。老插件没有 `/__remote_access__/notify`（会 404），外壳会照上面第三类那样报，
  但不会崩、也不会误报。
- **怎么知道手机上那一页跑的是哪份代码**：手机「设置 → 远程访问」底部写着
  `本页客户端 <版本> · <电脑上通知接口的状态>`。1.3.2 那次「发布了却没生效」就是栽在
  「插件装好了、手机上跑的却还是旧 client.js」上，所以 1.3.3 把这行自检加了上去。
- 关掉它有两种粒度（都在「设置 → 远程访问」）：「提问时通知手机」（宿主不再上报待答状态）
  与「仅窗口不可见时通知」（关掉后电脑窗口开着也照样提醒）。


## 构建

需要 **JDK 17+** 与 **Android SDK**（platform 34 / build-tools 34），Gradle 8.x：

```powershell
cd android
$env:JAVA_HOME = 'C:\Program Files\Android\openjdk\jdk-21.0.8'   # 换成你的 JDK
gradle assembleDebug          # 调试包：app/build/outputs/apk/debug/app-debug.apk
gradle assembleRelease        # 发布包（见下面的签名）
```

依赖只有 Android Gradle Plugin 8.8.0，没有 androidx / Kotlin —— 断网（`--offline`）也能构建。

### 签名（发布包）

仓库里**不放密钥**。要签发布包，自己在 `android/keystore.properties` 写（该文件已 gitignore）：

```properties
storeFile=C:/absolute/path/to/your.jks
storePassword=...
keyAlias=...
keyPassword=...
```

没有这个文件时，`assembleRelease` 产出**未签名**的 APK（也能装，但后续版本必须用同一把钥匙才能覆盖安装）。

生成密钥：

```powershell
& "$env:JAVA_HOME\bin\keytool.exe" -genkeypair -v -keystore dsh-remote.jks `
  -alias dshremote -keyalg RSA -keysize 2048 -validity 10950 `
  -storepass 你的口令 -keypass 你的口令 -dname "CN=DSH Remote, O=personal, C=CN"
```

> 注意 `storeFile` 用**正斜杠**（`C:/...`）：`keystore.properties` 是 Java Properties 格式，反斜杠会被当转义符吃掉。

## 发布

现成的包在 Releases 里（tag 形如 `v<versionName>`；应用名 **DSH**，图标是自适应图标 + 各密度 PNG）。换版本时：

1. `android/app/build.gradle` 里抬 `versionCode` / `versionName`（`versionCode` 必须比上一版大，否则覆盖安装会被拒）；
2. 构建、签名，把 APK 传上去；
3. 签名文件与口令放在**仓库外**，别提交。

命名约定（跟仓库改名一起对齐过）：**APK 的 `versionName` 与插件版本是同一个号**（仓库改名后从 `1.3.0` 起），
安装包叫 `dsh-plugin-remote-access-<versionName>.apk`，Release tag 叫 `v<versionName>`
（实际发过的就是 `v1.3.1` / `v1.3.0` / `v1.1.1` / `v1.1.0` / `v1.0.1`；更早的 `dsh-remote-1.1.1.apk`
是改名前的旧文件名，下载链接早就改成指向 Releases 页，不受影响）。

**唯一的例外：只动网页半区的那一版不重发 APK。** 那种版本只改 `client.js`（以及 `index.js` 里
与页面相关的小东西），手机上刷新一次页面就生效，再让用户装一遍 500KB 的 APK 没有意义 ——
这时插件版本往前走、APK 停在上一版，并在更新日志里写明（例如插件 `1.3.2` 时 APK 仍是 `1.3.1`）。
**反过来不成立**：动了外壳代码（Java / 清单 / 图标）就必须重打 APK 并抬 `versionCode`。

当前这一版：插件 **1.3.4** · APK **1.3.4**（`versionCode` 11）。`versionCode` 每次重打都必须比上一版大，
否则覆盖安装会被拒。

## 为什么单独一个 App

浏览器也能用，但手机上：

- 地址栏要手打 `http://` 加长串 IP，还容易打错；
- 打不开时看到的是一张错误页，**改地址得去翻浏览器历史**；
- 没有「下次直接进」的入口；
- 退到后台之后就没有了 —— **浏览器页面收不到「模型在等你选择」的提醒**（那需要一条前台服务）。

这个外壳就解决这四件事，网页本身（布局、设置、UI 设置）仍然全在插件里。
